# Sway

The whole desktop lives in one directory, `sway/.config/sway/`, which stow links to `~/.config/sway/`. Every app is started with an explicit path into this directory, so the stock `~/.config/<app>` locations are never read.

## Layout

- `config` sets the variables, then runs `include config.d/*`, then `include hosts/$(hostname)`.
- `config.d/` is the config split by topic into numbered pieces (`10-look`, `20-input`, `30-apps` and so on). They load in name order, and the variables in `config` must come first.
- `hosts/<hostname>` holds that machine's `output` lines. It loads last so it can override the shared pieces, and a missing file is skipped. See [machines.md](machines.md).
- `bin/` holds the scripts that bindings, waybar and the menu run.
- `apps/` holds the configs for waybar, fuzzel, swaylock and wiremix.
- `panels/` holds the Quickshell panels, the lock screen and the screensaver. Each one has an entry file at the top (`wifi.qml`, `bluetooth.qml`, `sound.qml`, `display.qml`, `power.qml`, `calendar.qml`, `notifications.qml`, `recording.qml`, `lock.qml`, `screensaver.qml`, `share.qml`) and a directory of the same name with its scripts and logic (`toggle`, `flow.mjs`, `display/ctl`, `lock/lock`).
- `panels/common/` holds what the panels share: `PanelShell.qml`, `Theme.qml`, `AdvancedLink.qml`, `Chip.qml` (the small button), `PanelCard.qml` (the card under the bar that every popup panel draws on) and `SectionLabel.qml` (the small section titles). display, power and calendar draw their card 20% bigger (`zoom: 1.2`); wifi, bluetooth, sound and the notification centre stay at normal size, since their lists can grow long.

The screen-share portal is set up in `nixos/common.nix` (`xdg.portal.wlr.settings`), not in a file here. The NixOS module starts `xdg-desktop-portal-wlr` with `--config` pointing at a file generated from those settings, so a config in `~/.config/xdg-desktop-portal-wlr` is never read. A file there, kept from the Arch setup, went unnoticed: the portal fell back to slurp as its picker, and `bin/share-picker` and the notification hiding never ran. The picker the portal runs is `bin/share-picker`. It captures each monitor with `grim -o` and a thumbnail of each window with `grim -T`, which works for a window on another workspace too, and shows monitors and windows as cards side by side in `panels/share.qml`, each window with its thumbnail, title and workspace. A side-by-side row fits any number of windows, where fuzzel's list with thumbnail-sized rows ran off a 1080p screen. Brave asks for a window twice, once for its preview and once to share, because the portal can restore only a monitor pick, so the picker remembers a window pick for 60 seconds and answers the second ask itself, once. The spec is [docs/specs/screen-share.md](specs/screen-share.md). A monitor pick hides notifications right away, before the portal starts the stream, and the portal's `exec_before` hides them again when a share starts without the picker. The portal runs `exec_before` only when no other share is live, so the pick is what covers a monitor share that starts during a window share. While a monitor is already shared or recorded, the picker shows no thumbnails, since it opens on the shared screen itself: each card shows the app's icon instead.

`/etc/sway/config.d` is not included. `bin/session-env` imports the session environment (`DISPLAY`, `WAYLAND_DISPLAY`, `SWAYSOCK`, `XDG_CURRENT_DESKTOP`) into systemd and D-Bus itself, then restarts `xdg-desktop-portal` so it picks the Sway portal config and screen sharing works.

## Scripts

Bash scripts start with `#!/usr/bin/env bash` because NixOS has no `/bin/bash`. POSIX scripts use `#!/bin/sh`, which NixOS does provide. The menu lists apps through Quickshell, which reads `.desktop` files from `XDG_DATA_DIRS` instead of `/usr/share`, since NixOS keeps them in the store and in profile directories.

## Binding titles

Every binding has a `#: <title>` comment on the line above it. `bin/keybindings` (`Super + K`) reads `config` first and then `config.d/*`, and shows that title for each binding. A binding without a title shows its raw command instead. Workspace bindings get generated titles. Picking a line in the list runs the binding, so the cheat sheet also works as a launcher.

## GPU order at startup

greetd runs `bin/start` (the path is set in `nixos/common.nix`). The script sets `WLR_DRM_DEVICES` with the integrated GPU first. wlroots renders on the first device in that list. Left alone, it picked the NVIDIA card, and every frame for the panel, which is wired to the iGPU, crossed between GPUs through CPU copies: high CPU use and a spinning fan. The NVIDIA card stays in the list, second, because the HDMI and DP ports are wired to it. Without it the external monitors go dark. On a machine with one GPU the ordering does nothing.

## Resume and external monitors

`display/reinit` runs after resume. With the proprietary NVIDIA driver, Sway keeps the external outputs marked active after a suspend while the screen stays black. Disabling and enabling each external output forces a new modeset. This is still needed with NVIDIA's suspend support enabled: on 2026-11-12 the external monitor stayed black without the hook.

## Waybar zombie processes

Waybar 0.15.0 can leave a zombie child (`.waybar-wrapped <defunct>`) each time it destroys a bar: on a reload, when an output goes away, or on resume from suspend or hibernation. It stops each module's thread with `pthread_cancel()`, and a module that is starting a command at that moment forks a child that inherits the pending cancel. The child dies before it runs the command, and the cancelled thread never waits for it, so it stays until waybar exits. A zombie holds no memory, only an entry in the process table, and a reload or a new login clears them. The bug is [Waybar issue #5369](https://github.com/Alexays/Waybar/issues/5369), fixed by [PR #5370](https://github.com/Alexays/Waybar/pull/5370) after 0.15.0. The fix arrives with the waybar release that `bin/update` brings in, and nothing in this repo works around it. `ps -eo stat,comm | grep -c '^Z'` counts them.

## Wi-Fi icon shows the interface name

Waybar 0.15.0 forgets both addresses of the Wi-Fi interface when any one of them is removed, which happens each time the temporary IPv6 address rotates. The network module then reads as "linked" (connected, no IP address), and without a `format-linked` it shows the interface name, such as `wlp0s20f3`, until the next IPv4 address event. `apps/waybar.jsonc` sets `format-linked` to the same signal icon as `format-wifi`, so the bar looks the same in that state. The fix is commit [1688611](https://github.com/Alexays/Waybar/commit/1688611), in Waybar 0.16.0. Once `bin/update` brings that release, the two `-linked` lines can go.

## Screen recording

`bin/record` records a region (`Ctrl + Print`) or the focused screen (`Ctrl + Shift + Print`) to an MP4 in `~/Videos/Screenrecords`. The Capture menu has the same two. The keys record video only. Capture in the menu also has Record area with microphone and Record screen with microphone, which add the default microphone for a narrated video (wf-recorder `--audio`). While it records, a small box in the bottom-right corner shows the elapsed time, and notifications are hidden, as during a screen share. Sway has no way to keep a window or a notification out of the capture, so the box shows up in the video when the recorded area includes that corner, and a notification would too. Pressing either key again, picking any record entry, or clicking the box or the red icon in the bar stops the recording. wf-recorder encodes with x264 on the CPU. It only encodes frames that changed, so the load stays low, and the notebook has no VA-API driver installed for the Intel GPU. The spec is [docs/specs/screen-recording.md](specs/screen-recording.md).

## Notifications

Notifications come from `panels/notifications.qml`, a Quickshell process that owns the freedesktop notification service and draws the popups in the top right corner of the focused monitor. It replaced mako so that notifications can be kept with their time and their actions for a notification centre. Unlike the other panels it is always running: `config.d/90-autostart` starts it through `panels/notifications/run`, which starts it again if it crashes. mako is no longer installed, because its D-Bus service file would let D-Bus start it whenever the Quickshell daemon is down, and the two would then compete for the same service name.

A left click runs the notification's default action, a right click dismisses it, and its other actions show as buttons. A popup stays 5 seconds unless the sender asks for another time, and a critical one stays until clicked. Popups that arrive together form a deck: the newest in front, older ones behind it with their top edges showing, so their number and border colours read at a glance without filling the right side of the screen. With the pointer over the deck it fans out into a list, and nothing times out until the pointer leaves. Do not disturb, a whole-screen share and a screen recording each turn on a mode that hides popups. They are separate modes, so ending a share never turns off a Do not disturb set by hand. During a share or a recording, one card takes the place of the popups and says only how many notifications arrived and why they are hidden, with no app name or text, so you know something came in without showing it. A critical one keeps the card on screen with a red border until clicked. Do not disturb shows nothing at all. Chromium browsers such as Brave already hide their own web notifications while they share the screen, but notifications from other apps, such as the Slack app, used to show. `bin/dnd` switches them over Quickshell IPC, and the modes on are saved in `$XDG_RUNTIME_DIR`, so they survive a restart of the daemon. Turning a share or recording mode on also takes the popups already on screen off it; they stay in the centre. A notification its sender replaces in place, with the same id and new text, counts as a new arrival: it pops up again for its full time and moves to the top of the centre. Chat apps do that for a message count, and poweralertd does it for its battery warnings, so the critical warning at 7% shows even after the one at 20% was dismissed from the screen.

The bell in the bar is grey when quiet, blue with the number of notifications that arrived since the centre was last opened, yellow in Do not disturb and red while a share or recording hides popups. A click on it, `Super + Ctrl + ,` or Notifications in the menu opens the notification centre: every notification of the session, newest first, with its time and actions. A click on an entry runs its default action, the close mark dismisses it, and Clear dismisses all. The centre also has the Do not disturb switch, and a middle click on the bell toggles it too. `Super + Ctrl + .` takes the popups off the screen and leaves them in the centre, and `Super + Ctrl + Shift + ,` clears everything, as Clear does. The centre lives inside the daemon, because only the daemon holds the notifications and can still run their actions. It uses the same `PanelShell` as the other panels with `keepAlive` set, so closing it hides the window instead of ending the process. The rules are in `panels/notifications/notify.mjs`. The spec is [docs/specs/notifications.md](specs/notifications.md). While a share or a recording hides the popups, the centre hides its list too, older entries included, and shows only how many there are, since opening it mid-share would put every entry on the shared screen. Its Show popups chip turns the mode off and shows the list.

A click on a notification runs its default action, but the app's window does not come forward, so a Slack or WhatsApp (Brave) notification leaves you on the current workspace. On Wayland an app can only raise its own window with an xdg-activation token tied to a real user input. The click lands on the daemon's popup, so the notification spec (1.2) has the server send that token in an `ActivationToken` signal right before `ActionInvoked`. Quickshell 0.3.0 declares the signal but never sends it. Sway would follow a valid token, since `config.d/10-look` sets `focus_on_window_activation focus`. Two ways out were weighed in November 2026 and left for later. One is a community patch for Quickshell that sends the token ([omarchy-pkgs #1367](https://github.com/omacom/omarchy-pkgs/pull/1367), [Jitsusama/core.nix #3168](https://github.com/Jitsusama/core.nix/pull/3168)): it targets Quickshell 0.3.2 while nixpkgs has 0.3.0, it is third-party code in the same program as the lock screen, and nobody has reported it working on Sway or with Slack. The other is a workaround in the daemon: after the action, focus the app's window with `swaymsg '[app_id="^<desktop entry>$"] focus'`, which picks the wrong window when Brave has more than one. The fix to wait for is a Quickshell release that sends `ActivationToken`.

The daemon also draws the popup of the volume, microphone and brightness keys: an icon, a bar and the value at the bottom centre of the focused monitor, gone 1.5 seconds after the last press. The media keys show the same popup with a play or pause icon and the track, which follows the player, so after next it changes to the new track as soon as the player reports it. The keys run `bin/osd`, which changes the value with `wpctl` or `brightnessctl` and then asks the daemon for the popup over Quickshell IPC. swayosd did this before, but it is a GTK4 program that used about 130 MB for this popup alone, while the daemon is running anyway. The spec is [docs/specs/osd.md](specs/osd.md).

## Battery warnings

UPower (`nixos/common.nix`) tracks the battery. On the notebook it hibernates at 4% (see [nixos.md](nixos.md#hibernation)); a machine without a swapfile powers off at 2% instead, since UPower's default hybrid sleep needs a disk swap. `poweralertd`, started in `config.d/90-autostart`, turns UPower's levels into notifications: low at 20%, critical at 7% on the notebook. It also sends a notification on every charge state change, such as plugging in the charger. The notification daemon never shows those, and shows the warnings with a red border until they are clicked, including while Do not disturb, a screen share or a recording hides everything else.

## Polkit agent

`polkit-gnome-authentication-agent-1`, started in `config.d/90-autostart`, shows the password dialog when an app asks polkit for an admin action, such as formatting a disk in GNOME Disks or opening a folder as administrator in Nautilus. Without an agent in the session those actions fail at once. NixOS keeps the agent in the package's `libexec/` directory, so `nixos/common.nix` adds `/libexec` to `environment.pathsToLink` and Sway starts it from `/run/current-system/sw/libexec`.

## Screensaver and lock timing

After 5 minutes idle, swayidle starts `panels/screensaver.qml`: every output shows the images of `~/Pictures/Wallpapers` in turn, dimmed, changing every 20 seconds with a fade, under a big clock and date that move to a new spot at each slide so nothing stays in one place on the panel. Two outputs start on different images. The screensaver is only a signal that the lock is coming: a key, a click or a mouse move ends it without a password. It holds the keyboard while it is up, so the key that ends it is not typed into the window you were using. The lock screen follows at 7 minutes and the screens turn off at 7.5 minutes. When the lock comes while the screensaver is up, the blurred backdrop of the lock shows the screensaver instead of your windows.

A fullscreen window holds all of this off (`inhibit_idle fullscreen` in `config.d/40-windows`), so a video or slides in fullscreen never get the screensaver or the lock, whether or not the app asks for it. The spec is [docs/specs/screensaver.md](specs/screensaver.md).

## Stay awake, night light and power profile

These three are in the Toggle menu, and each one shows in the bar. `bin/idle` (`Super + Ctrl + I`) stops the screensaver, the lock and the screen blanking while you are idle. It restarts swayidle without its timeouts instead of stopping it, so a suspend or a lid close still locks the session first. A cup icon in the bar shows while it is on. `bin/nightlight` (`Super + Ctrl + N`) warms the screen to 4000 K with gammastep until you turn it off, and shows a moon icon. There is no schedule. Each switch also shows a short popup at the bottom of the screen, in the same place as the volume popup, saying what changed ("Stay awake off", "Night light on"). Do not disturb and a profile picked in the menu show it too. Without it, turning something off gave no sign, because its bar icon only disappears. The power profile icon belongs to waybar's own `power-profiles-daemon` module: a green leaf for power-saver, a grey heart pulse for balanced and an orange bolt for performance. A click cycles them, and Toggle › Power profile picks one directly. On this Lenovo LOQ, `Fn + Q` changes the firmware mode itself in a loop of quiet, balanced and performance, which the kernel reports as `low-power`, `balanced` and `balanced-performance`. power-profiles-daemon 0.30 has no profile for `balanced-performance`, so on that step the icon stays on balanced, and it follows the other two steps about 2 seconds late. The daemon's own performance profile is the kernel's `performance`, which this machine maps to the BIOS extreme mode. A click on the battery icon opens the power panel, which also shows the time left, the power draw, the battery health and the charge limit. The charge limit is UPower's charge threshold, which on this Lenovo is the conservation mode. polkit lets the active user change it without a password. The spec is [docs/specs/power-panel.md](specs/power-panel.md). The specs are [docs/specs/stay-awake.md](specs/stay-awake.md) and [docs/specs/night-light.md](specs/night-light.md).

## Focus or run

`bin/focus-or-run NAME COMMAND` brings the open window of an app forward, and starts the app only when no window of it is open. `Super + M` (Spotify), `Super + Shift + S` (Slack) and `Super + Shift + T` (system tools) use it, so pressing the key again jumps to the app instead of opening a second copy. The name is matched against the window's app_id, or its class for an app running under XWayland, ignoring case. Browsers keep a plain key that opens a new window every time. The spec is [docs/specs/focus-or-run.md](specs/focus-or-run.md).

## Screenshots, color picker and the Print keys

The keys with `Print` follow one rule: the modifier picks the action and `Shift` takes the whole screen instead of an area. `Print` and `Shift + Print` take a screenshot, `Ctrl + Print` and `Ctrl + Shift + Print` record, and `Super` reads something from the screen: `Super + Print` the text in an area (below) and `Super + Ctrl + Print` the color of a pixel. Alt is left out because `Alt + Print` sends `Sys_Req` instead of `Print` on most layouts.

`bin/screenshot` saves the image in `~/Pictures/Screenshots`, puts it on the clipboard and shows a notification with an Edit button. Edit opens the image in satty for arrows, boxes, text or blurring something private; Enter or the copy button copies the edited image and saves it over the same file, and the save button only saves it. `notify-send` waits for that button for 10 minutes and then stops listening, so a later click on Edit in the notification centre does nothing. `bin/colorpick` runs hyprpicker, which shows a magnifier; a click copies the hex color and shows it in a notification. The specs are [docs/specs/screenshot.md](specs/screenshot.md) and [docs/specs/colorpick.md](specs/colorpick.md).

## Text from the screen (OCR)

`bin/ocr` (`Super + Print`, or Capture › Text from area in the menu) lets you drag a region, reads the text in it with tesseract in English and Portuguese, and puts the text on the clipboard. A notification shows how the text starts, or says that none was found. It works on anything on the screen: an image, a video call, a shared screen, a scanned PDF. Only the English and Portuguese language data are installed, since the default tesseract package carries every language. The spec is [docs/specs/ocr.md](specs/ocr.md).

## Clipboard history and emoji

`bin/clipboard`, started in `config.d/90-autostart`, stores every copy with cliphist. `Super + V` lists them in fuzzel, newest first, and the chosen one goes back on the clipboard. The history is kept in `$XDG_RUNTIME_DIR`, which is in memory, so it disappears at logout and never reaches the disk. System › Clear clipboard history empties it earlier, for example after copying a password by hand. Copies that a password manager marks as sensitive are never stored. `Super + .` opens `bin/emoji`, a fuzzel list of Unicode's emoji searched by English name. The pick is typed into the focused window with wtype and also left on the clipboard. The list is `emoji-test.txt` from the `unicode-emoji` package, which `nixos/common.nix` links into `/run/current-system/sw/share/unicode`. The specs are [docs/specs/clipboard-history.md](specs/clipboard-history.md) and [docs/specs/emoji-picker.md](specs/emoji-picker.md).

## Nautilus warm-up

`config.d/90-autostart` runs `nautilus --gapplication-service` at login. It opens no window and exits on its own after a few seconds, but on the way it starts the gvfs services (trash, network, phones, recent files) over D-Bus and loads Nautilus's libraries into the disk cache. Nautilus does not stay running after its last window closes, so every open starts it again; this makes the first open of a session as quick as the later ones.

## Panels

The panels are Quickshell windows. Each panel has a `toggle` script that kills the running panel or starts a new one, so a click on its waybar icon or menu entry opens and closes it. While a panel is open, a scanner or listener runs; once it closes, nothing keeps running.

A panel is a full-screen transparent `PanelWindow` on the overlay layer with exclusive keyboard focus. Esc closes it, and so does a click outside the visible card.

Exclusive keyboard focus does not follow a workspace switch. Switching workspace by key or by a click on another output would leave every window without input until the panel closed. So each panel listens to Sway's workspace events through `I3IpcListener` and closes itself on a focus change, the way a popup would. Sway also skips its own mouse warping while a layer surface holds the keyboard, so when the switch moves to another output the panel moves the cursor to the center of the new workspace before it quits.

All of this lives once in `common/PanelShell.qml`, and every panel except the lock screen is a `PanelShell` with its own card. Quickshell only loads files from the directory of the entry file it runs, which is why every entry file sits at the top of `panels/` and imports `"common"` and its own `<name>/` files from there. An import that leaves that directory passes qmllint but fails in Quickshell, so `bin/check static` also starts every panel in a headless Sway (step `panels-load`). A big panel splits into component files in its own `<name>/` directory, as the notification daemon does with its popups and centre. Those files import `"../common"`, which stays inside `panels/` and works. Quickshell's own `import qs.common` form also works there, but qmllint cannot resolve it, so the repo keeps relative imports. `common/Theme.qml` holds the colours and the font, and `common/AdvancedLink.qml` is the footer link that opens a panel's full TUI in a floating terminal. A fix to the shared behaviour goes there, so it reaches every panel at once.

Every `Text` in the panels that shows a value declares its format, and the static step `plain-text` fails when one does not. Qt's default format guesses: a string that looks like HTML is drawn as rich text, and rich text fetches the source of an `<img>` tag over the network. A notification title, a page title in the share picker, a track name or a Wi-Fi network name can carry such a tag, so the machine would contact an address someone else picked, which leaks its IP. Those texts are drawn as plain text. The notification body is the only styled text: it keeps bold, italic, underline, links and line breaks, and every other `<` is escaped by `Notify.safeBody`, so an image tag shows as text.

## Menu

`Super + Space`, or the menu icon at the left of the bar, opens the menu: a Quickshell panel in the middle of the screen with Apps, the top entries (Keybindings, Notifications, Clipboard history, Emoji) and the Capture, Style, Setup, Toggle and System submenus. Apps holds every installed app with its icon. The whole tree lives in `panels/menu/menu.mjs`, so typing searches every level below the one shown: from the top, "screen" lists the Capture entries with their path beside them, and "browser" finds Firefox by its generic name. The current level's own matches come first, then a line, then the deeper ones. Esc clears the search, then goes up a level, then closes. It follows the Omarchy menu, which keeps the whole tree in its own Quickshell shell. The fuzzel menu it replaces read the apps after drawing the first lines, so the entries jumped sideways when the app icons arrived, and its search at the top did not reach the submenus. The spec is [docs/specs/menu.md](specs/menu.md).

## Terminal opacity and text size

Alacritty's opacity is set live by `bin/opacity` through `alacritty msg config`. Text size is set by `display/ctl`, which edits `alacritty/.config/alacritty/alacritty.toml` in place. The edit shows up in `git status`. Commit it to keep the new size as the default, or check out the file to drop it.
